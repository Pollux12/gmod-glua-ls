These settings live under `gmod` in `.gluarc.json`. The defaults suit most addons and gamemodes.

## Realms

| Option | Default | Description |
|---|---|---|
| `gmod.defaultRealm` | `"shared"` | Realm for files with no realm signal: `"client"`, `"server"` or `"shared"` |
| `gmod.detectRealmFromFilename` | `true` | Use `cl_`, `sv_` and `sh_` file prefixes and `client`/`server` folders |
| `gmod.detectRealmFromCalls` | `true` | Use `include`, `AddCSLuaFile` and `IncludeCS` calls |

See [Wrong realm warnings](/getting-started/common-fixes#wrong-realm-warnings) for how realms are decided.

## General

| Option | Default | Description |
|---|---|---|
| `gmod.enabled` | `true` | Garry's Mod analysis. Do not turn this off, it is only for isolating bugs |
| `gmod.autoDetectGamemodeBase` | `true` | Load the base gamemode named in your gamemode's `.txt` file as a library |
| `gmod.inferDynamicFields` | `true` | Track fields you add to entities, players and other objects, such as `ply.Money = 0` |
| `gmod.dynamicFieldsGlobal` | `true` | Share those fields across all files. Set `false` to keep them per file |
| `gmod.fileParamDefaults` | built-in list | Types for common parameter names that have no `@param`, such as `ply` → `Player`. Set a name to `""` to remove a built-in entry |
| `gmod.outline.verbosity` | `"normal"` | Detail in the **Outline** view: `"minimal"`, `"normal"` or `"verbose"` |
| `gmod.templatePath` | none | Folder of your own templates for **New** in the Class Explorer. Built-in templates are used when a name is missing |

## Annotations

| Option | Default | Description |
|---|---|---|
| `gmod.annotationsPath` | none | Load the Garry's Mod annotations from this folder instead of the downloaded ones |
| `gmod.autoLoadAnnotations` | none | Set `false` to load no Garry's Mod annotations for this project |

See [Garry's Mod annotations](/configuration/annotations-management) for download options.

## Opening a whole Garry's Mod folder

When you open a whole Garry's Mod folder (named `garrysmod`, holding both `addons/` and `gamemodes/`, or holding a `garrysmod/` folder), GLuaLS treats it like a multi-root workspace of its addons and the gamemode you work on. Each addon and gamemode keeps its own module paths and its own `.gluarc.json`.

- Every addon loads.
- The active gamemode loads with the gamemodes it derives from, up to `base` or `sandbox`, which the annotations describe. The gamemodes that ship with Garry's Mod (`base`, `sandbox` and `terrortown`) otherwise load only when picked or while one of their files is open; `terrortown` also loads with a gamemode that derives from it.
- With no active gamemode, a sole custom gamemode loads. With several, each loads while one of its files is open in the editor; `glua_check` loads them all.
- Files outside the addons and gamemodes, such as `lua/`, are analysed while open.

Any other folder, such as one gamemode or the `addons/` folder, loads everything.

In VS Code, when the folder has several custom gamemodes and none is picked, GLuaLS asks which to load: **Addons only** (`""`), one gamemode, **Load all custom** (`"*"`), or **Load all** (`loadEverything`). For addon work, pick **Addons only**: the annotations already describe `base` and `sandbox`, and picking one of them loads its source on top. Run **GLuaLS: Select Gamemode** or click the status bar item to change it later. The pick is saved to `.gluarc.json` when the folder is in a git repository and has a `.gluarc.json` or no other config file, and otherwise to the workspace folder's settings.

| Option | Default | Description |
|---|---|---|
| `gmod.activeGamemode` | none | Gamemode folder to load with the addons. `"*"` loads every custom gamemode and `""` none, for working on addons |
| `gmod.loadEverything` | `false` | Load the whole folder, `lua/` and built-in gamemodes included |

## Net messages

| Option | Default | Description |
|---|---|---|
| `gmod.network.enabled` | `true` | Check `net.Start` / `net.Receive` pairs and their reads and writes |
| `gmod.network.completion.smartReadSuggestions` | `true` | Suggest the next expected `net.Read*` call inside a receiver |
| `gmod.network.completion.mismatchHints` | `true` | Mark suggestions that do not match the expected read |
| `gmod.network.codeLensEnabled` | `true` | Show a code lens above net message receivers |

To turn off one net check, add its code to `diagnostics.disable`. The codes are listed in [Diagnostics settings](/configuration/diagnostics#garrys-mod).

## VGUI

| Option | Default | Description |
|---|---|---|
| `gmod.vgui.codeLensEnabled` | `true` | Show a code lens above `vgui.Register` calls |
| `gmod.vgui.inlayHintEnabled` | `false` | Show the panel type after `:Add()` calls |

## Hooks

Use these when your project calls hooks through its own functions.

| Option | Default | Description |
|---|---|---|
| `gmod.hookMappings.methodToHook` | `{}` | Treat a method name as a hook, such as `{ "Think": "Think" }` |
| `gmod.hookMappings.emitterToHook` | `{}` | Treat a function that runs a hook as `hook.Run` for that hook |
| `gmod.hookMappings.methodPrefixes` | `[]` | Extra tables whose methods are gamemode hooks, such as `COMPONENT` |

## Scripted classes

GLuaLS recognizes entities, weapons, effects, tools, player classes, gamemodes, and plugins and schemas for frameworks such as Helix, based on their folders. Each type is a *scope* in `gmod.scriptedClassScopes.include`. You only need this setting to add your own class type or change a built-in one.

<Frame>
  <img src="/images/showcase/scripted-classes.gif" alt="The Class Explorer listing effects, entities and Helix plugins, then completing a gamemode hook in a Helix plugin" />
</Frame>

Built-in scope ids: `entities`, `weapons`, `effects`, `stools`, `player_classes`, `plugins`, `schemas`, `gamemodes`.

To change a built-in scope, add an entry with its `id` and only the fields you want to change. To add a new one, use a new `id`:

```json .gluarc.json
{
  "gmod": {
    "scriptedClassScopes": {
      "include": [
        { "id": "effects", "disabled": true },
        {
          "id": "controllers",
          "label": "Controllers",
          "classGlobal": "CTRL",
          "path": ["lua", "controllers"],
          "include": ["lua/controllers/**"],
          "rootDir": "lua/controllers",
          "scaffold": {
            "files": [{ "path": "{{name}}.lua", "template": "controller.lua" }]
          }
        }
      ]
    }
  }
}
```

| Field | Description |
|---|---|
| `id` | Name of the scope. Use a built-in id to change that scope |
| `label` | Name shown in the Class Explorer and settings panel |
| `classGlobal` | Global the class uses in its files, such as `ENT` or `SWEP` |
| `path` | Folder names that mark a file as this class type |
| `include` | Glob patterns for the class files |
| `exclude` | Glob patterns to skip |
| `rootDir` | Folder where **New** creates classes |
| `scaffold.files` | Files **New** creates: `{ "path", "template" }`, where `{{name}}` is the class name |
| `fixedClassName` | Use this class name instead of one taken from the folder name |
| `classNamePrefix` | Text added before the folder name, such as `gamemode_` |
| `isGlobalSingleton` | Merge every matching file into one class |
| `aliases` | Other globals that refer to the same class |
| `superTypes` | Types the class inherits, such as `GM` |
| `parentId` | Scope to nest this one under in the Class Explorer |
| `icon` | VS Code icon id for the Class Explorer |
| `disabled` | Set `true` to turn the scope off |
