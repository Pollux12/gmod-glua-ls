Most projects never need these settings.

## Runtime

| Option | Default | Description |
|---|---|---|
| `runtime.nonstandardSymbol` | GLua symbols | Extra syntax the parser accepts. See below |
| `runtime.requireLikeFunction` | `[]` | Your own functions that load modules like `require` |
| `runtime.requirePattern` | `[]` | Path patterns for `require`, such as `"?.lua"` and `"?/init.lua"` |
| `runtime.special` | `{}` | Treat your own functions like a built-in: `"require"`, `"error"`, `"assert"`, `"type"`, `"setmetatable"` or `"none"` |
| `runtime.extensions` | `[]` | Extra file extensions to read as Lua, such as `".lua.txt"` |

`runtime.version` has no effect. Garry's Mod always uses LuaJIT.

### GLua syntax

By default GLuaLS accepts the GLua additions `//`, `/* */`, `continue`, `!=`, `||`, `&&` and `!`. If you set `runtime.nonstandardSymbol`, your list replaces the default, so include these too. Other accepted values are `` ` ``, `+=`, `-=`, `*=`, `/=`, `%=`, `^=`, `//=`, `|=`, `&=`, `<<=` and `>>=`.

```json .gluarc.json
{
  "runtime": {
    "requireLikeFunction": ["MyAddon.Load"],
    "special": {
      "MyAddon.Assert": "assert"
    }
  }
}
```

## Strict mode

These settings make type checks stricter. They catch more mistakes, but also report more false warnings in loosely typed code.

| Option | Default | Description |
|---|---|---|
| `strict.allowNullableAsNonNullable` | `true` | Allow a value that may be `nil` where a non-`nil` value is expected. Set `false` for stricter `nil` checks |
| `strict.inferredTypeMismatch` | `false` | Report type mismatches for values without an explicit type |
| `strict.strictTypeCoercion` | `false` | Report the automatic string and number conversions GLua allows |
| `strict.arrayIndex` | `false` | Treat values read from arrays as possibly `nil` |
| `strict.requirePath` | `false` | Match `require` paths exactly instead of finding the closest module |
| `strict.requireExportGlobal` | `false` | Only use globals from libraries when they are marked `---@export global` |
| `strict.docBaseConstMatchBaseType` | `true` | Let a plain `integer` or `string` match an alias of literal values, such as `---@alias id 1 \| 2 \| 3` |
| `strict.metaOverrideFileDefine` | `true` | Let definitions from `---@meta` files override definitions in code |

## Documentation comments

| Option | Default | Description |
|---|---|---|
| `doc.syntax` | `"md"` | Format of documentation comments: `"md"`, `"myst"`, `"rst"` or `"none"` |
| `doc.knownTags` | `[]` | Extra annotation tags to accept without an `unknown-doc-tag` warning |
| `doc.privateName` | `[]` | Field name patterns to treat as private, such as `"m_*"` |
| `doc.rstPrimaryDomain` | none | Primary domain for `"rst"` and `"myst"` |
| `doc.rstDefaultRole` | none | Default role for `"rst"` and `"myst"` |

## Resource paths

| Option | Default | Description |
|---|---|---|
| `resource.paths` | `[]` | Folders used to open file paths in strings with `Ctrl+Click`, such as `materials/` and `sound/` |
