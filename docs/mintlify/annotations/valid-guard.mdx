## Overview

`valid_guard` marks a function such as `IsValid` that returns `true` only when its first argument is a valid object. After the check, GLuaLS treats the value as valid, so `need-check-nil` and `unchecked-nil-access` stop warning about it.

The official annotations already mark `IsValid` and similar Garry's Mod helpers.

---

## Syntax

```lua
---@return TypeGuard<T>
---@[valid_guard]
```

Put it after the `@return` line. The function must return `TypeGuard<T>`.

---

## Example

```lua
---@param ent Entity?
---@return TypeGuard<Entity>
---@[valid_guard]
function IsValidEntity(ent) end

---@type Entity?
local ent

if IsValidEntity(ent) then
    ent:GetClass() -- ent is valid here
end
```

A value that already has a more specific type, such as `PhysObj` or `Panel`, keeps that type after the check.

---

## Keep it narrow

Only use `valid_guard` on a function that really checks validity. Marking a function that does not hides real `nil` and `NULL` bugs.

It applies only to calls of the annotated function. A local function with the same name is a separate function.
