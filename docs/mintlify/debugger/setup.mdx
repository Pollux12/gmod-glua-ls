---
title: Set up the debugger
description: Install the debugger module and connect VS Code to your local server.
---

The debugger connects VS Code to a running Garry's Mod dedicated server (SRCDS) through a small binary module called `gm_rdb`. It is meant for local development servers.

<Warning>
Do not install `gm_rdb` on a public or production server. It lets a connected debugger run any Lua on the server.
</Warning>

## Set up with the wizard

<Steps>
  <Step title="Start the wizard">
    Click **GLuaLS** in the status bar and choose **Setup Debugger**, or run **GLuaLS: Configure Debugger** from the Command Palette (`Ctrl+Shift+P`).
  </Step>
  <Step title="Answer the prompts">
    The wizard asks for your SRCDS folder (it usually finds it for you), the server's platform, and how your project maps to the server's files. It then:

    - Installs `gm_rdb` into `garrysmod/lua/bin/`
    - Adds `garrysmod/lua/autorun/debug.lua`, which starts the debugger when the server loads
    - Adds a **[SERVER] Attach to SRCDS** entry to `.vscode/launch.json`
  </Step>
  <Step title="Restart the server">
    Restart SRCDS so it loads the module.
  </Step>
  <Step title="Connect">
    Open **Run and Debug** (`Ctrl+Shift+D`), pick **[SERVER] Attach to SRCDS** and press `F5`.
  </Step>
</Steps>

The extension keeps `gm_rdb` and `debug.lua` up to date and asks before installing an update.

## Debug the client

The wizard can also install the client module (`rdb_client`) into your own Garry's Mod install. It then adds a **[CLIENT] Attach to Gmod** entry to `launch.json`.

Join your server with that game install, then start **[CLIENT] Attach to Gmod**. The client part of `debug.lua` comes from the server, so the server needs to be set up first.

<Warning>
With the client module installed, any server you join that runs a matching `debug.lua` could start the debugger in your game. Remove the module when you are not using it.
</Warning>

## launch.json options

The wizard writes these for you. You only need to edit them if your layout changes.

| Option | Default | Description |
|---|---|---|
| `host` | `"127.0.0.1"` | Address of the server |
| `port` | `21111` | Debugger port. The client uses `21112` |
| `sourceRoot` | `${workspaceFolder}` | Folder that server paths are resolved from |
| `sourceFileMap` | `{}` | Maps folders on your machine to paths on the server, such as `"${workspaceFolder}": "addons/my-addon"` |
| `stopOnEntry` | `true` | Pause as soon as the debugger connects. The wizard sets this to `false` for the server |
| `stopOnError` | `false` | Pause when a Lua error happens. This includes errors in other addons |
| `realm` | `"server"` | Where **Run Lua** commands run by default: `"server"`, `"client"` or `"shared"` |

If breakpoints never hit, `sourceFileMap` is usually wrong. Each entry should map your project folder to the same folder as seen from `garrysmod/`.

## Manual setup

Use this only if the wizard fails.

1. Download the module for your server from the [GitHub releases](https://github.com/Pollux12/gmod-glua-ls/releases): `gmsv_rdb_win64.dll`, `gmsv_rdb_win32.dll`, `gmsv_rdb_linux64.dll` or `gmsv_rdb_linux.dll`.
2. Put it in `garrysmod/lua/bin/` on the server. Create the folder if it does not exist.
3. Create `garrysmod/lua/autorun/debug.lua`:

   ```lua garrysmod/lua/autorun/debug.lua
   if SERVER then
       require("rdb")
       rdb.activate(21111)
   end
   ```

4. Add an attach entry to `.vscode/launch.json`:

   ```json .vscode/launch.json
   {
     "version": "0.2.0",
     "configurations": [
       {
         "type": "gluals_gmod",
         "request": "attach",
         "name": "[SERVER] Attach to SRCDS",
         "host": "127.0.0.1",
         "port": 21111,
         "sourceRoot": "${workspaceFolder}/../..",
         "sourceFileMap": {
           "${workspaceFolder}": "addons/my-addon"
         },
         "stopOnEntry": false
       }
     ]
   }
   ```

This minimal `debug.lua` is enough for breakpoints and stepping. **Run Lua** on the client and **Refresh GLua File** need the full file the wizard writes.

## Server launch options

Add these to the SRCDS command line only if you need them:

| Option | Effect |
|---|---|
| `-rdb_allow_remote` | Accept debugger connections from other machines. By default only the same machine can connect |
| `-rdb_pause_on_activate [seconds]` | Pause the server when the debugger module starts, so you can debug startup code. It resumes after the timeout, 60 seconds by default, or `0` to wait forever |

<Warning>
Only use `-rdb_allow_remote` on a network you trust, and open the debugger port in the firewall only for your own machine.
</Warning>
